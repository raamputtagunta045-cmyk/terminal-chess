# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A personal Python practice directory. The substantial piece is `chess_game.py` — a
self-contained chess game with a negamax engine, plus `test_chess_game.py` (191 tests).
`practice1.py` and `rock_paper_scissors.py` are unrelated early exercises.

No dependencies beyond the standard library. `pytest` and `coverage` are dev-only.

## Commands

```bash
python chess_game.py                       # play (interactive; needs a real terminal)

python -m pytest -q                        # full suite (~25s; includes perft(5))
python -m pytest -q -m "not slow"          # skip perft(5) (~4s)
python -m pytest -q -k castling            # single topic
python -m pytest -q test_chess_game.py::TestEnPassant::test_capture_removes_correct_pawn

python -m coverage run -m pytest -q -m "not slow"
python -m coverage report --show-missing --include=chess_game.py
```

Use `python -m pytest`, not `pytest` — Python here is the Microsoft Store build and
its `Scripts/` directory is not on PATH.

## Architecture

Everything lives in `chess_game.py`, in four layers:

**Board state.** `squares` is a flat 64-element list where **index 0 is a8 and index 63
is h1** — rank 8 first, matching FEN order. Uppercase is White, lowercase Black, `.` empty.
Position is completed by `white_to_move`, `castling` (a set drawn from `KQkq`), `ep`
(the en-passant target square index, or `None`), and the halfmove/fullmove clocks.

**Move generation.** A move is the tuple `(from, to, promotion)`, promotion being `None`
or an uppercase piece letter. `gen_pseudo()` produces pseudo-legal moves; `legal_moves()`
filters them by playing each one and testing king safety. `attacked(sq, by_white)` works
*backwards* from the target square — casting rays and knight/pawn/king offsets outward and
asking what sits there — rather than enumerating every enemy move.

**Search.** `Engine.choose()` runs iterative deepening; `negamax()` is alpha-beta with a
capture-only `quiesce()` at the horizon. Exceeding the time budget raises `TimeUp`, which
unwinds to `choose()`, where the last completed depth's result is used. The `blunder`
parameter makes weaker difficulty levels pick randomly among moves within N centipawns of
best — that is the *only* source of engine randomness.

**Notation and CLI.** `move_to_san()` renders SAN (it needs the legal-move list to decide
disambiguation); `parse_move()` accepts either coordinates or SAN. `main()` is the
interactive loop and is deliberately untested — it accounts for essentially all of the
uncovered lines.

## Invariants worth preserving

**`make()`/`unmake()` must stay perfectly symmetric.** `make()` returns an undo record;
`unmake()` consumes it. The search leans on this and never copies the board, so any
asymmetry corrupts the position mid-search and produces baffling results. `TestMakeUnmake`
guards this two plies deep across five positions.

**Evaluation sign conventions differ by layer.** `evaluate()` returns centipawns from
**White's** point of view. `negamax()` and `quiesce()` negate it to the **side to move**.
`Engine.choose()` therefore returns a score from the *mover's* perspective — flip it before
displaying to a human. This has already caused one bug.

**Piece-square tables are written a8-first**, so White indexes them directly and Black
mirrors vertically with `idx ^ 56`.

**Perft is the regression gate.** Any change to move generation must keep
`TestPerft` green — it checks the start position to depth 5 (4,865,609) plus four standard
reference positions covering castling, en passant, and promotion. Unit tests alone will not
catch move-generation bugs.

## Known sharp edges

Positions are assumed legal. `king_sq()` raises `ValueError` if a king is missing, and
move generation will happily capture an enemy king if handed a position where one is en
prise. Unreachable through normal play, but malformed FENs crash rather than erroring
cleanly — relevant if `Board.from_fen()` ever takes untrusted input.

`analyze complexity` rates this file "Very Complex" (cyclomatic 260). Most of that is
`gen_pseudo()`'s per-piece-type branching, which is normal for a move generator.

## Environment notes

This directory is **not a git repository** — there is no version control on the engine or
tests.

`ruflo` scaffolding (`.claude/`, `.claude-flow/`, `.swarm/`, `.agents/`, `ruvector.db`,
`.mcp.json`, ~5.6 MB) was generated by `npx @claude-flow/cli init` and is not used by the
chess code. `npx @claude-flow/cli cleanup` removes it. Note that its background daemon
spawns headless `claude` sessions on an interval and consumes tokens continuously; stop it
with `npx @claude-flow/cli daemon stop`.
